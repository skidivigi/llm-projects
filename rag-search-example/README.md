# RAG Search Lab

Учебный стенд для экспериментов с поисковой частью RAG. Цель — на практике понять, как размер чанков, размерность векторов, параметры поиска и reranker влияют на релевантность выдачи.

Принцип экспериментов: фиксируем документы и контрольные вопросы, меняем один параметр и сравниваем результаты.

## Стек

- Python 3.13.7 через pyenv; окружение и зависимости — uv.
- PyTorch 2.9.1 с CUDA 12.8;
- Sentence Transformers и `intfloat/multilingual-e5-small` — векторы размерности 384.
- Qdrant 1.16.2 в Docker — хранение векторов и поиск.

Embedding-модель работает на GPU в Python-процессе, Qdrant — на CPU в контейнере.

## Текущее состояние

Первый шаг выполнен: модель создаёт embeddings для трёх учебных фрагментов, скрипт записывает их в Qdrant и выводит top-3 с текстом, score и временем выполнения. Каждый фрагмент пока является одним чанком. Используются cosine similarity и точный поиск.

Для вопроса «Как подключиться к рабочей сети из дома?» первым найден фрагмент про VPN. Высокий score сам по себе не гарантирует полезность фрагмента и не является вероятностью правильного ответа. При top-3 из трёх документов в выдачу попадает вся коллекция.

Генерация ответа через LLM пока не подключена.

## Запуск

Нужны Ubuntu/WSL2, настроенные pyenv и uv, работающий Docker Compose и доступная GPU (`nvidia-smi`). Команды выполняются из корня репозитория:

```bash
pyenv install -s 3.13.7
pyenv local 3.13.7
uv sync --python "$(pyenv which python)"
docker compose up -d
uv run python check_env.py
```

Свой вопрос:

```bash
uv run python check_env.py "Сколько времени сохраняются бэкапы?"
```

Первый запуск скачивает модель. Проверочный скрипт при каждом запуске обновляет три точки с постоянными ID, затем выполняет поиск. Коллекция: `rag_lab_smoke_e5_small`.
